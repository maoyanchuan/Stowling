# 分类任务主基线

记录日期：2026 年 11 月 25 日。
流程标识：`classification-baseline`。适用范围：独立分类任务的一轮执行。

## 本轮用户确认与状态

原有三项已并入主基线，状态为 **已并入主流程**：

- 同类多盒合批：同一分类尽量连续准备并运输多盒，遵守真实背包空间和打包预留。
- 按来源物品处理不满盒缓存：以来源库存和本批任务物品确定需求，仅处理相关类别。
- 分类箱满后继续交付其他物品：已确认满箱余物暂留背包，继续其他可投递物品。

三项执行不再受实验开关控制。旧保存值无论 true、false 或缺省都使用同一新基线。
本轮同时将以下改动标记为 **已废弃** 并删除实现、入口与执行配置：

- `classification-multi-source-fixed-order`（分类取料与交付顺序）。
- `classification-empty-box-cache-settlement`（空盒收尾复用本轮库存）。

分类继续使用原有单来源取料／交付循环及仓储排版择箱规则；删除多来源固定箱序实验循环。
空盒结算使用既有开箱盘点流程，不保留被删除的缓存结算路径。
旧文档中的多来源混合批次和固定箱序重构草案不再作为当前执行约定。
本轮合并依据是用户明确指令；构建与测试的实际执行情况另行记录，不代替游戏验证。

## 输入与输出

- `cacheLocationRef`：任务实际配置的物品来源坐标点或容器区域。
- `classificationAreas`：按任务页面保存顺序执行的分类区。
- 分类区及绑定组的识别规则、储存方式、散货配额、不满盒位置、站位及打包位置。
- `remainderPolicy`：不可分类和总溢出的独立开关、存放位置及总溢出先打包设置。
- 任务级机器人仓库开关、位置及纯盒／杂盒配置。
- 中断收尾、空盒仓库、来源合计留存上限、锁定栏位及真实任务物品账本。

输出按服务器确认量记录交付、来源余物、满箱或受阻目标及资源收尾结果。
只处理任务拥有的物品，保留玩家原有物品和锁定栏位。

## 正常顺序

```text
固定本轮任务配置与账本
    ↓
按保存顺序进入分类区，盘点／复用来源库存并解析目标
    ↓
从来源库存和携带任务物品确定本区实际需求
    ↓
仅为有需求的类别接入不满盒缓存
    ↓
按原有来源循环取料，同类多盒合批，依次投递可用目标
    ↓
确认满箱余物暂留，其他可投递物品继续；无可处理物品则结束本区
    ↓
进入后续分类区，继续尝试接收携带余物及来源物品
    ↓
全部分类区完成 → 不可分类 → 机器人仓库 → 总溢出
    ↓
核对背包，处理余物，盘点并结算空盒，完成收尾
```

### 进入分类区与取料

1. 来源库存由本轮已读取的服务器记录和已确认存取更新；需要首次盘点时正常开箱读取。
   分类标记、精确物品、多物品绑定等规则沿用真实分类区配置。
2. 本区合并需求只由任务来源库存及携带任务物品触发，包含未改名盒内的真实物品键。
   不满盒辅助缓存不能以自己的存货反向触发需求；没有本区分类物品时跳过辅助缓存。
3. 有需求时只处理相关类别，保持当前来源循环，不进入被删除的多来源批次执行器。
4. 同类盒子连续准备、集中运输；遵守未锁定背包容量和原有打包／回收预留。
   尾批直接交付，不等待新投料凑满，不借用目标散货配额凑满盒。
5. 普通、混合、纯盒储存及指定不满盒位置继续执行其生效配置。
   同类准备后的其余物品沿用既有批次规则，不因本次合并新增其他运输策略。

### 交付与满箱余物

1. 先交付本批仍能接收的目标；同类还有其他可用箱时继续尝试。
   目标顺序沿用原有仓储排版与择箱策略，删除实验性的固定箱序分支。
2. 按服务器确认的实际接收量入账，保留本轮确认的完整目标库存与按物品核验的容量结果。
   寻路、开箱或打包受阻不视为满箱，未知容量不能据此判定为溢出。
3. 所有相关已解析目标均确认放满时，余物暂留背包及任务账本。
   先交付其他物品，不立即退回来源再重新取出，也不为相同证据重复跑分类箱核容量。
4. 当前区没有其他可投递或可取物品时结束本区；后续分类区仍可接收这批余物。
   区域结束检查只放行明确暂留的满箱余物，任务最终核对仍要求完整清账。
5. 受阻但未确认满箱的物品保留原有换箱、来源归还或中断收尾处理。

### 剩余处理与收尾

任务 UI 将不可分类、总溢出和机器人仓库统一放在“溢出处理”子菜单内，
仍保存各自的开关和位置；菜单摘要显示以下真实执行顺序，不改变本节执行规则。

1. 全部分区匹配完成后，按真实开关将不可分类物品送往不可分类位置；关闭时保留来源。
2. 已确认所有对应目标均满的物品，按“机器人仓库 → 总溢出”顺序处理。
   仅执行已开启功能；仓库按纯盒／杂盒规则接收盒装物品，总溢出按普通“先打包”开关接收余量。
3. 复用本轮确认的分类目标容量证据；未知目标按既有逻辑实际核验。
   不能将不可分类或受阻物品冒充溢出，也不在总溢出后重新绕回仓库。
4. 背包核对、余物归还和最终断言继续执行，暂留物品始终属于本任务，不能提前清账。
5. 空盒结算恢复既有来源开箱盘点和留存处理。来源合计保留配置上限，多余空盒归仓，
   不主动从仓库补足来源留存数量。删除“不额外扫描、只用缓存”的实验实现。
6. 临时潜影盒、在途点击和未确认物品必须收尾完成，按真实结果汇总。

## 完成、失败与中断

- 全部完成：分类区与已开启剩余处理均执行，任务账本清理完成，临时资源已回收。
- 尚有余物：余物必须有明确位置和原因；关闭接收功能不表示允许丢弃任务物品。
- 无法确认存取、余物无法归还或临时盒无法回收时，报告具体阶段并进入既有中断收尾。
- 用户取消或抢占时停止新增取料，等待在途确认，再处理全部真实任务物品和临时资源。
  暂留的满箱物品同样参与中断收尾，不以阶段过滤结果代替真实账本。
- 详细约定引用 [中断收尾](../task-cleanup.md) 与
  [公共容器交互](../container-interactions.md)。

## 已并入主流程：分类在安全节点暂停进食

- 标识：`classification-food-safe-pause`。
- 状态：**已并入主流程**。2026 年 11 月 26 日按用户明确要求合并，仅独立分类任务生效。
- 删除 `foodPauseResumeEnabled` 及原抢占分类的实验分支；旧配置的所有取值统一迁移。
- 输入：本轮分类的冻结配置、执行栈、任务物品账本，以及更高优先级的自动进食任务。
- 顺序：请求暂停 → 完成当前模块及其服务器确认、打包和临时盒回收 →
  到下一次导航之前的安全节点 → 确认导航停止 → 执行进食（包括配置的补给和收尾）→
  刷新背包观察 → 恢复原执行栈，重新导航后再进行下一次存取。
  尚未开始的分类也可在首个模块前暂停；不在“已到达箱子、尚未存取”之间暂停。
- 暂停保留原 run ID、分类进度、任务物品归属和已确认库存，不生成另一轮分类，
  不调用分类的中断收尾，不重复已确认的存取。下一次开箱按现有交互读取真实容器状态。
- 等待安全节点期间不取消正在执行的模块；大范围扫描或打包尚未完成时会延后进食。
  导航停止状态未知时保留执行槽位并报告失败，不能交给进食任务继续操作。
- 进食完成、失败或被取消后，均等待进食自身的安全收尾结束，再恢复分类；
  背包观察不可用时等待恢复。进食失败不代表分类成功，不重建分类任务。
- 暂停期间用户取消分类：记录取消，进食释放槽位后仅执行分类中断收尾，不恢复正常步骤。
  强制停止沿用原强停语义；其他高优先级任务仍使用原抢占流程。
- 完成与失败条件沿用本文主基线；暂停自身不完成任务，也不清理任务物品账本。
- 不可堆叠专属余物模块执行期间等待模块完成，再到安全节点进食。
- 页面删除两项已合并实验的入口、提示与徽标，分类无实验项时隐藏整个菜单。
- 合并依据为用户明确指令；此前报告进食后出现容器界面但分类可继续，
  额外右键保护也已按用户确认并入 [自动进食基线](auto-eat.md)。
- 验证：维护同一实例续接、取消、其他任务隔离、旧配置迁移与专属步骤测试源码。

## 已并入主流程：总溢出先打包

- 标识：`classification-total-overflow-packing`；状态：**已并入主流程**。
  2026 年 11 月 27 日按用户明确要求合并，作为独立分类的普通可选设置。
- 普通业务开关：`remainderPolicy.overflowPackingEnabled`，默认 `false`；
  旧配置缺省仍为关闭，已有 true／false 值原样保留，不新增替代字段或配置迁移分支。
- UI 位于“溢出处理 → 总溢出”的存放位置下方，名称为“总溢出先打包”。
  不受页面调试显示控制；分类不再显示该项的实验入口、徽标或空实验菜单。
  收起菜单、关闭总溢出、保存及重新打开均保留打包值；关闭总溢出时不执行打包。
- 仅独立分类任务生效，须同时开启总溢出。关闭打包时直接转存；开启后所有送入所选
  总溢出位置的任务物品都先装盒。不可分类引用同一位置时同样打包，其他位置沿用原规则。
- 正常顺序：确定本次待存物品 → 检查总溢出各容器内已有内容且可接收的盒子 →
  优先续装、填满这些盒子 → 再使用任务空盒或空盒供应 → 回收并整盒存入总溢出。
  前一容器只有空盒时仍继续检查后续未满盒；真实余物不足一盒时允许不满。
  携带的未改名不满装货盒先拆出任务物品用于续装，满盒和改名盒整盒存入。
  允许杂盒与不满盒，不新增纯盒选择；机器人仓库继续使用自己的纯盒／杂盒配置。
- 输入为本次任务物品、已确认满箱证据、总溢出位置、空盒供应及打包位置配置。
  不可堆叠区专属余物、其他不可分类位置、拾取和旧组合任务不接入此策略。
- 不可分类 → 机器人仓库 → 总溢出的既定顺序保持；仓库处理后的余量再进入总溢出。
- 完成要求实际存入并确认任务账本；空盒不足、打包或存放失败时保留物品并报告受阻，
  不自动降级为散货，不把受阻或未知容量当作分类满箱。
- 中断收尾使用运行开始时冻结的同一开关。指定收尾容器与总溢出重叠时，在原位置顺序
  上使用打包通道，所有任务余物均可进入，不限于已确认满箱物品。总溢出后备同理。
  散货优先续装已有未满盒；收尾携带的装货盒整盒存放，不拆盒或借其续装散货。
  临时盒回收、账本归属和其他后备顺序沿用原约定。
- 本次没有新增调试开关，不保留另一条实验执行分支；原字段作为普通业务开关继续使用。
