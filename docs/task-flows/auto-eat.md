# 自动进食主流程与调试改动

记录日期：2026 年 11 月 26 日。

## 已知主基线

输入为指定食物、饱食度阈值、检查间隔、任务优先级、自动补给位置与数量、优先身上食物。
饱食度监听达到阈值后提交任务；按设置先补给或优先使用身上锁定的指定食物。
连续进食至饱食度达到 20，按实际消耗更新锁定食物账本；补给食物默认锁定自用。
补给失败、食物不可用或使用超时按真实结果失败；取消等待本次使用确认后收尾。
进食释放自己按下的使用键、还原手持栏位，再释放执行槽位。
独立分类在安全节点暂停、进食收尾后恢复同一运行，详见 [分类基线](classification.md)。

现有隐藏行为：进食通过持续按下使用键保持动作，任务轮询在客户端 tick 尾部执行。
原版在两次轮询之间发现使用已结束、使用键仍按下时，可再次执行准星交互并打开容器。
用户报告物品界面未关闭但任务仍正常寻路、执行；提供的进食日志本身未记录原版开箱。

## 待验证：进食期间阻止额外右键交互

- 标识：`auto-eat-world-use-guard`。
- 执行开关：`worldUseGuardEnabled`，默认 `false`，保存到该进食任务的 `autoEatOptions`。
- 关闭：保持上述主基线；手动进食、其他任务不会获得新行为。
- 开启：仍直接调用物品使用接口开始／重试进食，持续按住使用键保持动作；
  仅在本次自动进食活动期间阻止原版重新发起准星交互，覆盖吃完至轮询释放按键的间隙。
  不转动视角，不选择附近方块，不通过关闭未知容器补救。
- 成功、失败、超时、取消与玩家不可用时，均在释放按键后清除交互保护；
  下一次进食重新读取任务执行值，补给开箱与恢复分类的主动存取不受保护影响。
- 完成和失败条件保持主基线；保护自身不消费物品、不调整任务顺序，也不接管容器。
- 页面底部实验性设置默认收起，仅调试显示开启时展示；隐藏或收起不改变保存值。
  已开启任务始终显示改动名称和标识。
- 与已合并分类功能无开关依赖；只在开启该进食任务修复时生效。
- 状态：**待验证**。维护保护生命周期、额外右键拦截、默认关闭、API 与配置往返和 UI 测试。
  实际测试与构建结果交付时记录；游戏验证由用户执行。
