# 分类区的多站位与子区绑定

改动标识：`classification-standing-subregions`。状态：**待验证**。

## 主流程与开关

分类主流程继续以 [独立分类](classification.md) 为准。未启用实验时，使用原绑定组、
原识别区／储存区和生效的单点 `standingArea`，不读取新站位列表执行，不改变其他任务。
既有标记容器刷新未应用组内站位；实验关闭时也保留这一事实，不借本次修改修正。

独立分类任务新增 `standingSubregionsEnabled`，默认 `false`，唯一入口位于任务底部的
“实验性设置”。页面调试显示仅控制入口显示，隐藏或收起不修改保存值；任务始终显示已开启
改动的名称和标识。仅独立分类任务可执行该实验，普通任务、拾取、刷新缓存、组合任务隔离。
本实验不依赖其他实验，不改变分类、打包、溢出、暂停与中断收尾的顺序。

## 输入与配置

- 每个绑定组基础配置保存 `standingPlan`，包含独立的 `enabled` 和 `points` 列表。
- 每条记录包含脚下方块坐标 `position`、`subregionsEnabled`、两个子区草稿
  `markerArea`／`storageArea`，以及独立的 `expanded` 展开状态。启用子区时两者必须
  成对提供，分别位于本组识别区与储存区内；不启用时代表整个绑定组并保留子区草稿。
- 多站位的储存子区不允许重叠，避免同一容器分配到不同站位。标记子区允许共享，
  以便一个识别箱对应两段储存区。执行仅涉及声明的子区，编辑器提示覆盖全部需要操作的容器。
- 未启用或未完成的坐标保留草稿；开启时要求至少一条完整有效记录。关闭独立设置只恢复
  业务参数继承，不删除或停用本组站位；关闭指定站位则停用约束并保留全部记录。
- 旧配置第一次编辑时，以当前生效单站位初始化一条记录，子区缺省为整个组。
  无旧站位时初始化关闭的空列表。原 `categoryOptions` 和 `standingArea` 暂留作实验关闭
  时的基线，界面显示基线摘要；正式合并须经用户验证确认后再清理旧字段与执行分支。
- 保存、复制、重新打开以及单片拓展保留列表。拓展时站位、子识别区、子储存区共同平移；
  独立设置中的识别规则仍遵守原有绝对坐标约定。

## 正常执行

1. 本轮任务冻结配置，只有独立分类且实验开启时，生成本轮使用的分类区快照。
2. 对开启站位的绑定组，按记录顺序生成对应子识别区／子储存区执行绑定；
   各自携带指定站位，脚下 Y 加 1 后接入原寻路与到达判定。
3. 关闭指定站位的组使用整个原识别区与储存区，不指定站位；不回落到旧全局单站位。
4. 识别容器刷新、分类目标解析、后续存取使用同一份快照。共享识别容器只读取一次，
   使用首次对应记录的站位，缓存供共享该标记的子绑定使用。
5. 容器只从所属子区的站位操作；不按距离切换到其他站位，也不扩大为站位之间的区域。
   原可达性、交互距离与遮挡判定继续生效。既有目标选择顺序与业务参数保持。

## 完成、失败与中断

完成仍要求真实服务器确认存取并完成原任务账本与资源收尾。站位或子区配置无效时拒绝保存
或启动，并提示所在绑定组；子区跨界、储存子区重叠和双箱跨站位子区均不自动选一个站位。
不可达或够不到容器沿用原失败与收尾路径，不改成满箱，不自动改用未指定站位。
暂停、取消与中断使用本轮冻结快照，不重新套用编辑中的坐标。

## 验证约定

维护 Java 与 pytest 测试源码：实验默认关闭／关闭保留主流程、开启分区站位、关闭指定站位、
独立设置隔离、旧配置初始化、保存复制、单片平移、子区校验、标记容器与储存容器站位，
以及普通任务与刷新缓存隔离。未经另行授权不运行新功能测试或代码检查；构建使用 `assemble`。
实际游戏验证由用户执行，本文件不因构建成功更新为已验证或已并入主流程。
