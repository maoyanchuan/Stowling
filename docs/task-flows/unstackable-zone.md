# 不可堆叠分类区

记录日期：2026 年 11 月 26 日。状态：**待验证**。

## 配置约定

坐标页复用“识别模式”的“不可堆叠分类”选项，不增加资源类型或模式下拉。
该模式作用于整个分类区；绑定组仍可独立设置储存、站位和拓展范围，识别方式统一。
展示框样品沿用已有大类：盔甲、船、药水、唱片等；潜影盒、改名物品不参与。
普通识别排除和多物品绑定草稿保留，在启用本次执行改动后不执行。
专属溢出保存到全局 `categoryOptions.unstackableOverflowRef`，缺省为空。
位置可引用坐标点或容器区域，必须独立于来源及分类储存容器。

## 主流程与调试差异

主流程保持 [分类任务主基线](classification.md)，已有不可堆叠大类识别不变。
改动标识：`classification-unstackable-zone-routing`。
任务执行开关：`unstackableZoneRoutingEnabled`，默认 `false`。
开关位于分类任务底部实验性设置，独立于运行、展开和页面调试显示偏好。

关闭时保持原有识别执行，不新增区域溢出步骤，专属溢出配置仅保存。
开启后，进入不可堆叠区时使用本轮独立执行副本，清除生效的通用识别与多物品追加规则，
保留原配置草稿；每区完成正常投递后执行该区专属余物处理。
通用分类区仍走原流程。此改动与原有任务溢出独立，无隐含覆盖其他实验。

## 输入、执行与输出

输入为任务物品来源、完整分类区、展示框识别和储存绑定、专属溢出位置。
正常顺序：盘点来源 → 解析本区大类 → 正常分类投递 → 本区专属溢出 → 后续区域。

专属溢出仅处理不可堆叠物品：未匹配本区大类，或本区对应目标全部确认放满。
开箱、寻路失败及未知容量不能当作满箱。已有大类样品的匹配范围不扩大为通用物品。
本区接管的不可堆叠物品不再进入后续分类区、任务不可分类、机器人仓库或总溢出。
多个不可堆叠区按任务顺序执行，前区已接管余物不再交给后区；同套大类的多个储存位置
应放在同一个分类区的绑定组中，避免区域溢出提前接收后区计划处理的物品。
未配置专属溢出时保留来源；携带余物沿用既有归还与中断收尾，不丢弃或提前清账。
专属溢出容器按服务器确认量入账；混装盒仅分离本次符合条件的物品。

完成条件：分类与可执行的专属溢出完成，所有任务物品有明确位置，最终账本正常核对。
失败条件：配置资源失效、目标与来源重叠、专属容器满或存取无法确认。
失败及用户中断均停止新增取料，沿用 [中断收尾](../task-cleanup.md) 处理真实任务物品。
专属溢出失败不能自动切换到公共或任务级溢出。
