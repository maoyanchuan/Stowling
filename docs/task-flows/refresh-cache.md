# 刷新缓存任务

## 用户确认的主基线

2026-11-26，用户明确同意将“连续开箱复用安全槽位”和
“刷新时优先原地开箱与就近寻路”并入主基线，并将
“分类区仅刷新储存容器”移为刷新缓存任务内的普通开关。
前两项状态为“已并入主流程”，删除实验入口、旧执行字段及被替代分支。
本任务没有剩余实验项，不显示空的实验性设置菜单或实验生效徽标。

## 输入与范围

- 输入：普通区域或分类区引用、容器类型、手动／每日／间隔触发配置。
  箱子、木桶、潜影盒默认启用，其他容器默认关闭。
- 普通设置 `categoryStorageOnlyEnabled`：默认 `false`，保留已保存值。
  在选区下方显示“分类区仅刷新储存容器”，无需开启页面调试模式。
- 选择分类区时需开启该开关；关闭时保留引用和配置，但前后端均阻止启动并提示开启。
  不将关闭解释为允许扫描识别区或整个总选区。普通区域不受此开关影响。
- 分类区仅取全部绑定组的生效 `storageArea` 并集；过滤未启用容器类型，双箱去重。
  跨边界双箱优先取储存区内的一半；识别区、组间空隙和总选区不扩大扫描范围。
  旧参数即使要求扫描识别区，也不更新分类标记缓存或将识别区纳入库存。

## 执行顺序

1. 将选区按区块切片，先收集所有已加载的选区切片。
2. 每次开箱都重新检查交互距离，优先读取当前位置够得到的待刷新容器。
   双箱任一入口可达即可读取；允许在该绑定组站位之外原地读取，不修改保存的站位。
3. 周围没有可达待刷新容器时，按到绑定组站位区域的最近三维距离选择目标。
   无站位配置时按最近入口距离选择，沿既有寻路处理障碍和拾取避让。
   原地交互仍检查实时距离和拾取避让；条件不满足时按该目标原站位寻路。
   这是就近访问规划，不承诺全局最短路径。
4. 本次刷新固定使用专属读取会话，首次准备安全手持槽位并等待同步，此后连续复用。
   每箱仍校验手持安全；逐箱等待菜单完整同步及 Chest Tracker 缓存更新，不并发开箱。
5. 已发现容器处理完毕后，按当前位置重新选择最近的未加载区块，导航并等待加载。
   加载后继续以上扫描和开箱顺序。
6. 全部处理完毕后报告刷新数量；单箱失败继续后续容器，最终汇总失败。

## 输出、完成与失败

输出为 Chest Tracker 库存缓存与任务结果，不搬运、分类或打包物品。
全部扫描和开箱成功为完成；储存区无容器时正常完成，不回退扫描识别区。
断开世界、区块无法加载、开箱失败或缓存未更新为失败，沿用现有超时与失败汇总。
不因本轮合并缩短确认等待或加入新的重试策略。

## 中断与收尾

完成、失败汇总、停止和世界断开时释放本次读取会话。
停止时取消当前导航与开箱，不再打开下一个容器，关闭属于本次访问的容器。
在原玩家仍可操作时恢复借用的背包槽和原快捷栏选择；断线后不操作新玩家背包。
单箱失败继续后续容器，后续重新准备安全槽位；异常退出也释放会话。

## 内部识别刷新与公共调用

分类任务的内部 `markerOnly` 刷新保留原识别流程，不使用本次合并的就近访问和手持复用。
普通分类、存取和其他公共调用保持原交互策略，仍遵守各自站位与避让约定。
`scanMarkers`、`includeMarkersInInventory` 等内部能力不作为手动刷新的新入口。

## 配置迁移

- 读取和保存刷新步骤时，移除 `reuseSafeHandEnabled`、`nearbyRouteEnabled`。
  旧值为 `true`、`false`、缺失或无效文本均不再决定执行；手动和定时刷新统一使用新基线。
- 迁移递归处理嵌套步骤与分支，保留任务 ID、目标、类型、触发配置及其他有效字段。
  只清理刷新步骤中的上述字段，不改写其他模块的参数。
- 保留 `categoryStorageOnlyEnabled` 名称、默认关闭与已保存值；它是普通业务开关。
  移除 `refresh-reuse-safe-hand`、`refresh-nearby-route` 和
  `refresh-category-storage-only` 的实验状态标识，后者只保留普通控件 ID。
