# 分类指定站位：范围判定与落稳开箱

标识：`classification-standing-range`。状态：**待验证**。
执行字段：`AutoClassifyDefinition.standingRangeEnabled`，默认 `false`。
仅独立分类任务生效，普通任务、拾取、组合分类及单独刷新缓存不接入。

## 主流程与实验差异

关闭时保持 [指定站位主流程](category-standing-bindings.md)：脚下方块 Y 加 1，
按整数脚部坐标判断，不改变原有导航、开箱或失败处理。

开启时保留配置、分类顺序、绑定组、离散站位和实际交互距离，仅调整带指定站位的
分类标记读取、目标导航和存取开箱。无指定站位的来源、打包和仓库动作保持原流程。
本改动与已合并的多站位及连续容器访问共用目标，不覆盖它们的规则。

## 输入、执行与输出

输入为本轮冻结的开关、所属绑定的站位、玩家实际位置与接地状态、运动速度和目标箱。
仍填写脚下方块坐标，运行目标携带本轮实验标记，不修改坐标配置，不使用全局执行状态。

1. 水平范围仍为指定方块范围；多个离散站位不连接成连续区域。
2. 脚部高度范围为脚下方块 Y + 1/16 至 Y + 1 + 1/8，另加 1e-5 浮点余量。
   覆盖下半砖、地毯、箱顶、灵魂沙和完整方块顶面，不逐种维护名单，不允许跨楼层。
3. 寻路候选包含该高度带对应的整数脚部目标；到达及开箱使用相同范围判定。
   必须接地且水平运动速度不超过每 tick 0.03 格，真实交互距离和拾取避让仍需满足。
   尚未落稳时继续原导航或等待，不提前取消到站过程。
4. 重新对齐指定站位时不因当前脚部坐标而排除该站位；原有最多两次导航重试、
   重试间隔和容器访问超时保持，不新增无限等待或自动换站位。
5. 落稳后切换安全手持并开箱；切手期间再次核验。存取仍按服务器确认量记账。

输出和完成条件沿用分类主流程：真实确认存取、清理任务账本及临时资源。
真实不可达、距离不足、超时或存取失败时沿用换箱、来源归还及中断收尾，
不把受阻当满箱，不改变任务最终成功状态的既有语义。
取消、暂停、进食及收尾沿用本轮冻结配置，释放导航和容器资源。

## 界面与验证

入口位于分类任务底部的“实验性设置”，名称“分类站位：范围判定与落稳开箱”。
默认收起，仅调试显示开启时显示；隐藏、收起、保存和重新打开不改变执行值。
已启用时任务卡始终显示改动标识。页面显示偏好与执行开关独立。

需覆盖高度带各表面、负高度、落脚与移动、范围边界、真实距离、唯一站位重新对齐、
双箱、标记读取、目标存取、开关持久化及 API 往返、其他任务隔离和隐藏入口保值。
自动验证与构建结果在交付记录补充；实际游戏验证由用户执行，尚未并入主流程。
