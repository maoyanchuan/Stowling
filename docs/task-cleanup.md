# 任务级中断存放与恢复

任务配置使用 `cleanupPolicy`：

```json
{
    "destinationRef": "coordinate:<UUID>",
    "resumeMode": "CONTINUE"
}
```

`destinationRef` 支持共享坐标和共享区域。自动分类未指定时使用本任务缓存区域，
恢复方式固定为 `RESTART`。旧普通任务未指定时沿用原公共暂存设施。
收尾存放位置、空潜影盒供应箱和后备打包位置在任务内设置。
坐标和区域删除检查包含这些引用。

收尾顺序：等待在途操作确认、回收本任务放置的潜影盒、将任务拥有的物品
散装或整盒存入指定位置。已有内容的盒子不在收尾中拆分或继续分类。
指定位置无法接收时，按任务已有溢出开关处理。玩家原有工具和食物仍受背包账本保护。

分类任务的收尾沿用本次运行启动时的配置快照：指定存放位置放不下时，先尝试已开启的
“机器人仓库”，再尝试已开启的“总溢出”，分别使用各自所选位置。机器人仓库遵守
纯盒／杂盒模式，只接收已确认属于分类溢出的物品，不接收不可分类物品。
收尾不会重新遍历物品来源，也不会拆分已有装货盒；纯盒模式下无法整盒接收的杂盒
保留在任务账本中并提示收尾受阻。已有装货盒不作为收尾散货的续装盒。
“不可分类”仍只在正常分类完成后执行，不作为中断收尾的通用存放位置。
关闭总溢出或机器人仓库后，不使用保留的目标草稿；新配置不回退到旧公共溢出设施。
旧普通任务中显式使用 `PACK_OVERFLOW` 的流程继续兼容原公共溢出。

机器人仓库优先已由用户验证并确认合入默认分类流程，不再提供优先级调试开关。
旧配置中的调试字段读取时移除，旧分类步骤迁移至上述同一顺序。
中断存放优先、只处理任务背包、不拆盒及在途确认和临时资源回收约定保持不变。

普通任务可选择 `CONTINUE`，紧急抢占后的重排会保留工作区、已完成的顶层阶段
和交付记录。当前未完成的顶层阶段重新执行，物理缓存记录失效后重新核对。
条件和循环内部的执行位置不会单独续接，因此当前阶段必须能依据交付记录重新核对需求。
取消任务不自动续跑；重复任务正常完成后的新一轮使用新进度。
这些运行进度在当前游戏进程内保留，不跨游戏重启保存。

材料收集模块使用 `context.workspace().progress()` 跟踪运行中确认的交付：

- `recordDelivery(position, moved)` 只记录实际确认存入的数量。
- `deliveredTo(position)` 查询本次逻辑任务对该位置的交付记录。
- `remainingAt(position, requested)` 计算尚需交付的精确物品键与数量。

公共存入模块和中断收尾已在确认存入后记入此账本；调用方不要重复记账。
例如需求 1000 个石头、中断收尾确认交付 400 个后，剩余需求为 600。
「自动收集材料」上传 `.litematic` 后保存解析出的用料清单。运行时从当前维度的
Chest Tracker 库存定位来源，开箱确认后按需取料，再分批送到所选容器或区域。
背包有空间时会继续到下一个来源取料。「按潜影盒交付」默认允许不同种类的材料混装。
开启「每盒只装一种材料」后，同种材料分批取到时会继续补当前的未满盒，装不下才开下一盒。
符合当前装盒方式且在缺口之内的现成整盒可直接搬运。散料用当前任务供应箱中的空潜影盒装箱，
清单里的空潜影盒单独交付。
「液体材料」可选择用普通冰替换水桶或跳过水桶，两个选项均关闭时照常收集水桶。
跳过岩浆可独立设置。
启动和中断恢复时重新盘点交付位置，已有材料会抵扣需求。仓库缺货时，任务进度会列出
仍缺的物品与数量，已交付的材料留在目标处。
