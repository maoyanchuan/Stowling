## 用户已确认的设计选择

| 项目 | 基线约定 |
| --- | --- |
| 分类区顺序 | 按任务页面保存的顺序逐区执行，完成当前区后再处理下一区。 |
| 批次组成 | 每批允许多种物品，按目标顺序逐一交付。 |
| 受阻处理 | 记录受阻目标，继续其他可处理物品，结束时汇总。 |
| 多来源取料 | 依次从多个来源箱取料，背包接近可用容量后统一交付。 |
| 同物品多目标 | 按分类区识别出的固定箱子顺序；满箱或受阻后尝试下一个。 |

以下步骤将这五项选择展开成一条可审阅的完整流程。
未在上表中确认的细节属于本草案建议，不能据此直接修改运行行为。

## 输入与输出

输入沿用真实任务配置：

- `cacheLocationRef`：页面中的“物品来源”，支持已配置的坐标点或容器区域。
- `classificationAreas`：有序的目标分类区引用。
- 分类区及绑定组的生效识别规则、储存方式、散货配额、打包区域和指定站位。
  绑定组启用独立设置时使用组配置，否则继承分类区全局配置。
- `remainderPolicy`：不可分类与溢出存放的独立开关、位置。
- 任务级 `overflowEnabled`、`overflowDestinationRef`、`robotWarehouseMixedBoxes`：
  机器人仓库开关、位置和纯盒／杂盒方式，区别于溢出存放。
- `cleanupPolicy`：中断存放、恢复方式及空盒仓库、缓存空盒留存配置。
- 本轮任务物品账本、真实背包、锁定栏位和已确认的服务器容器内容。

输出应能说明：各目标实际接收的物品和数量、来源剩余物品、不可分类物品、
确认溢出的物品、受阻位置及原因、空盒去向和未完成的回收／存放。
批次允许混合多种物品，不等于允许忽略储存规则将不同物品装入同一个潜影盒。

## 正常顺序

```text
启动并固定本轮配置
    ↓
按页面顺序进入一个分类区，扫描来源并解析目标
    ↓
沿来源列表连续取料，组成允许多种物品的批次
    ↓
按分类区目标顺序交付本批；满箱或受阻则尝试同类下一箱
    ↓
本批余物归还来源并记录原因，继续取下一批
    ↓
当前区没有可继续处理的物品 → 进入下一个分类区
    ↓
全部分类区结束 → 不可分类 → 溢出存放 → 机器人仓库
    ↓
核对任务物品、结算空盒、回收临时资源、汇总结果
```

### 1. 启动

1. 固定本轮配置和目标分类区顺序。运行中编辑的配置用于下一轮。
2. 核对必需引用、维度及物品来源，建立本轮账本和来源容器列表。
   必需引用失效或无法确定任务输入时，报告失败，不替换为其他位置。
3. 只接管任务明确拥有或明确交给本次分类的背包物品，保留玩家原有物品和锁定栏位。
4. 本轮以来源容器列表为遍历边界。容量根据真实未锁定栏位、已有货物及打包／回收预留
   计算；“接近可用容量”不另设未经确认的百分比。

### 2. 进入当前分类区

1. 重新读取来源库存；需要容器内容标记时先刷新标记，再解析当前分类区。
2. 生成“可接受物品 → 有序目标箱子”的映射，保留分类区识别出的排版及箱子顺序。
   不按距离或历史容量记录重排；历史记录可供展示，不能代替本次实际存取确认。
3. 应用已有识别规则、精确物品匹配、不可堆叠分类和多物品绑定。
   标记规则引用[坐标分类规则记录](../coordinate-classification-handoff.md)，不在此重写。
4. 解析结果记录进本轮跨区汇总；当前区未匹配不代表全局不可分类。
   若局部目标或标记无法解析，记录受阻范围；无法确定的物品不能判成不可分类。

### 3. 连续取料组成一批

1. 沿本轮来源列表依次访问，取出当前分类区匹配且仍有可尝试目标的物品。
   一个来源取完后，背包仍能继续安全取料就访问下一个来源，不立即返回交付。
2. 一个批次可以包含不同物品，也可以包含符合目标储存方式的现成货盒。
   需要拆开的混装盒只提取本阶段匹配部分，其余归还来源；拆盒和回收纳入同一账本。
3. 目标要求打包时，遵守该目标的生效储存方式与资源预留。
   不为凑同类多盒而占满整批，不等待后续投料凑满，不为凑满盒借走目标散货配额。
4. 继续取料会占用必需预留空间、来源列表已到末尾，或剩余来源已无可取物品时，
   结束取料并交付已有批次。尾批直接交付，不等待满背包或满盒。
5. 来源无法访问时记录来源受阻，继续其他来源；本轮不自动反复访问同一受阻位置。
   空批次不触发空跑交付。

### 4. 按固定顺序交付

1. 按当前分类区识别出的目标顺序处理本批物品；同物品多个箱子使用固定箱子顺序。
2. 到达该目标声明的站位或交互范围，开箱并等待服务器内容就绪。
   明确指定的站位、打包区域不因失败而被其他位置暗中替换。
3. 仅存入该目标接受的物品，执行目标生效的普通、散货盒子混合或纯盒储存规则。
   混合储存保留配额内散货，仅打包超额部分；纯盒只交付符合规则的货盒。
4. 每次只按服务器确认的实际接收量记账。部分接收后，携带余量继续尝试下一同类箱子。
5. 实际确认无接收容量的目标记为“已满”；寻路、开箱、打包位置、空盒等问题记为
   “受阻”。目标满箱或受阻后继续同类下一箱，再继续本批其他物品。
6. 本批所有可尝试目标访问后，将仍携带的任务余物归还物品来源并记录原因。
   若原来源无法接收，转入任务明确配置的中断存放；不能归还或安全回收时记录收尾受阻。
7. 本轮当前区已无可继续处理的物品时进入下一区，否则从尚有可取货物的来源继续组批。
   已归还的受阻物品在本区本轮内跳过；下一区仍可按自己的匹配结果尝试接收。

### 5. 全部分类区后的剩余处理

剩余处理只读取已开启功能及其位置，顺序固定：

1. **不可分类**：所有分类区均已成功完成相关匹配，且没有任何目标接受的物品。
   开启时送往不可分类位置；关闭时留在来源并计入汇总。
2. **溢出存放**：存在匹配目标，且所有对应目标均实际确认已满的物品。
   开启时先直接转存；放不下的余量归还来源，再进入下一步。
   只要仍有对应目标受阻或容量未知，就不能仅凭本轮未存入将物品判成溢出。
3. **机器人仓库**：只接收已确认属于分类溢出，且溢出存放未开启或未能接收的物品。
   开启时按任务纯盒／杂盒配置装盒并入库；不接收不可分类物品，不直接存入散货。
4. 已关闭的功能保留配置草稿，但不参与执行；不使用旧公共设施作自动后备位置。
   对应位置受阻或所有已开启位置放不下时，余物保留在来源或明确的中断存放位置，
   汇总位置、数量与原因，不重新绕回分类循环。

### 6. 正常收尾

1. 核对本轮确认存取量与任务账本，将本批余物放回来源或明确的中断存放位置。
2. 回收任务放置的临时潜影盒，确认没有在途点击、未归还余料或未回收资源。
3. 按空盒配置结算：优先使用来源空盒，不足时仅从已开启的空盒仓库补给。
   仓库关闭时只在来源内取用、回收；开启时多余空盒归仓。
   开启缓存留存时，全部来源容器合计保留至配置上限，不从仓库主动补足留存数量。
4. 输出本轮结果；有受阻或未处理物品时必须列出，不能只显示“分类成功”。

## 完成条件、失败与中断

- **全部交付完成**：所有分区与已开启后处理已执行，待分类物品已交付，
  任务账本核对完成，临时资源已回收。
- **本轮结束但有余物**：有限来源和目标均已处理，余物有明确位置、数量与原因，
  在途操作已确认且临时资源已回收。包括功能未开启、目标受阻或确认溢出无处接收。
  本文描述结果语义，不要求本次新增任何运行状态枚举。
- **不能正常完成**：必需输入失效、物品数量或归属无法确认、在途操作未确认，
  或余物／临时盒无法安全收回。记录具体阶段并进入中断收尾，不将未知结果记为交付。
- 单个目标受阻不结束整轮；先结束该目标的操作并确认货物可继续处理，再尝试其他目标。
  无法确认物品状态时不能继续移动这批物品，记录收尾受阻和待恢复内容。
- 用户取消或任务抢占后停止新增取料，等待在途确认，回收任务临时盒，
  将任务物品整盒或散装放到任务中断存放位置；不拆已有货盒继续分类。
- 中断存放接收不了时，仅按已开启的溢出存放、机器人仓库顺序尝试，仍须符合溢出资格；
  不可分类位置不作为中断通用存放位置。细节引用[中断收尾约定](../task-cleanup.md)。
- 恢复时重新扫描并从本流程起点重建本轮计划，不沿用失效的箱内记录或旧批次执行位置。

## 当前实现中已发现的差异与隐藏行为

本节是已知事实清单，不是第二条主流程，也不要求穷尽历史实现。

| 阶段 | 当前实现事实 | 与草案的关系 |
| --- | --- | --- |
| 取料循环 | 模板在一个来源箱内反复取料、交付，再换来源。 | 与连续多来源组批不同。 |
| 同类合批 | `sameCategoryBoxBatching` 缺省及默认值均为 `true`。 | 与多物品共享批次的基线不同。 |
| 拆盒打包 | 取料模块可先进入缓存拆盒、合批，完成后再决定是否普通取料。 | 后续须显式归入取料阶段。 |
| 择箱 | 排版内的同物品目标还会按容量记录和距离选择。 | 与固定箱子顺序不同。 |
| 导航 | 纯盒模式可跳过模板导航，改由存入／补盒流程前往目标。 | 后续须明确实际站位时机。 |
| 受阻 | 导航或存入失败可改记目标不可用，再尝试同组下一箱。 | 保留继续处理意图，分开原因。 |
| 来源回退 | 无目标时可存回当前来源，并延后本次来源中的对应分类。 | 多来源批次须显式记录回退位置。 |
| 打包位置 | 共享实现可选用后备打包点；另有暂存与余料归还路径。 | 不能自动认定为已确认基线。 |
| 最后核对 | 模板会同步背包并循环将新接管的任务物品存回来源。 | 须防止变成隐含的新一轮分类。 |
| 中断收尾 | 存放、溢出、机器人仓库另有共享执行路径及旧任务兼容。 | 改造不能影响其他任务。 |

核对入口：

- [任务生成][factory]：分区顺序、剩余处理和空盒结算。
- [流程模板][templates]：当前单来源取料／交付循环、缓存回退和最后背包核对。
- `WithdrawItemsModule`：进入普通取料前可能执行缓存拆盒与打包。
- `TaskRunWorkspace`、`ClassificationRoutePlanner`：目标选择、不可用与来源回退记录。
- `MoveToCoordinateModule`、`DepositItemsActionModule`：跳过导航、失败换箱与数量入账。
- `MinecraftStorageAutomation`：共享拆装盒、容量择箱、补盒、余料和中断处理。
- [任务及分类配置说明](../ui/task-ui-prompt.md)：现有业务字段与储存配置归属。
- [公共容器交互](../container-interactions.md)：服务器确认、锁定栏位及停止约定。
