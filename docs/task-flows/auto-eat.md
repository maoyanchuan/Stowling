# 自动进食主基线

记录日期：2026 年 11 月 26 日。

## 主基线

输入为指定食物、饱食度阈值、检查间隔、任务优先级、自动补给位置与数量、优先身上食物。
饱食度监听达到阈值后提交任务；按设置先补给或优先使用身上锁定的指定食物。
连续进食至饱食度达到 20，按实际消耗更新锁定食物账本；补给食物默认锁定自用。
补给失败、食物不可用或使用超时按真实结果失败；取消等待本次使用确认后收尾。
进食释放自己按下的使用键、还原手持栏位，再释放执行槽位。
独立分类在安全节点暂停、进食收尾后恢复同一运行，详见 [分类基线](classification.md)。
刷新缓存开启 `refresh-food-safe-pause` 实验后，也通过同一调度机制交出执行槽位；
暂停边界和原实例续刷约定见 [刷新缓存](refresh-cache.md)。关闭该实验时仍沿用原抢占。

## 已并入主流程：进食期间阻止额外右键交互

状态：**已并入主流程**。2026 年 11 月 26 日，用户确认游戏验证没有问题并明确要求合并。
原改动标识 `auto-eat-world-use-guard` 的实验使命已完成，删除独立开关与状态徽标。

- 自动进食仍直接调用物品使用接口开始／重试，持续按住使用键保持动作。
- 每次成功开始自动进食时固定启用当前客户端的交互保护，直到释放该次进食拥有的使用键。
  原版在食物消耗后、任务轮询释放按键前发起的额外准星交互会被阻止。
- 不转动视角，不选择附近方块，不以关闭未知容器作为补救。
- 成功、失败、超时、取消和玩家不可用时均先释放按键，再结束保护、还原手持栏位。
  非客户端线程取消正在保护的进食时，安排客户端线程完成释放。
- 连续进食每次重新建立、结束保护；保护不消费物品、不改变饱食度条件和任务顺序。
- 手动进食及没有自动进食活动时保持原版交互；补给开箱、分类主动存取在进食之外照常执行。
- 完成、失败与中断条件沿用上文主基线，不新增执行开关或回退分支。

## 配置迁移与界面

读取旧配置时移除 `autoEatOptions.worldUseGuardEnabled` 和已保存步骤的同名参数。
旧值为 true、false 或缺省均进入同一保护基线，后续保存和 API 回传不再包含该字段。
任务 ID、优先级、监听状态、食物、补给位置和数量、优先身上食物设置保持原值。

页面删除该实验行、提示、徽标与自动进食的空实验菜单，运行状态和正常设置继续分别维护。
页面调试显示不再影响自动进食，通用任务 UI 模板的视觉和交互规范不变。
